BISHENG WORK / ENGINEERING DESIGN REVIEW

企业知识库接入与商业授权

以 bisheng-gateway v1.6.0 为基准：保留基础席位，独立授权知识能力；网关负责准入与商业合同，Bisheng 负责用户数据与资源权限。

基准 8f9390b0 · v1.6.0设计提案 · 待实现2026-10-09 · 未部署验收

四个边界，一条用户身份链

推荐内置知识库插件，复用企业登录。插件提供上传与检索 tools；企业 token 只驻留在 Electron main。知识库检索结果进入 Work 当前 Agent，答案由现有模型链路生成。

复用现有机制新增或扩展模块（绿色区域）

产品交互归 Plugin

bisheng-work-knowledge 提供空间列表、上传状态、检索片段与来源定位。首期内置，后续支持企业市场受控更新。安装成功不等于获商业授权。

商业判断归 Gateway

校验 API 权限上限和授权有效期；每次请求读取有效授权投影。购买额度是企业合同，空间访问是数据权限，两者都必须满足。

资源权限归 Bisheng

复用真实用户、组织和文件可见性。付费不带来管理员权限，空间可见不代表全部文件可见。引用打开再次校验。

设计默认：企业已有 Bisheng 私有部署。可扩展托管 SaaS，但订单、支付与订阅控制面独立；不把支付逻辑或向量检索算法堆进网关。

把 Gateway 做成明确的准入层

保留 Spring Cloud Gateway / WebFlux。控制面走既有 Controller；知识数据面走独立 route + GatewayFilter。不新增整套业务 BFF，也不复刻 Bisheng 权限模型。

请求 ID / 格式限制→Token v2 + scope→席位 / 会话→企业知识 feature→速率 / 并发→可信用户委托→Bisheng ACL + 额度

顺序为设计逻辑；具体 Filter order 需组合验证，尤其 WebFilter、route GatewayFilter、body cache 之间的先后关系。

客户端凭证与内部委托分别验证

凭证发行方 / 接收方合同
旧 accessGateway → 旧模型接口保留 HS256、bisheng-dsh-model，禁止用于知识 API
Work access v2Gateway → Gateway Work API单一资源入口 audience bisheng-work-api；版本、scope、sub、tenant、seat、session、grant_version；签名可继续使用独立派生 HS256 密钥，只在 Gateway 验证
内部用户委托Gateway → Bisheng Work 专用适配层非对称签名、独立 kid、aud=bisheng-work-backend；建议 30 秒；绑定主体、操作、method、内部 path、request_id、policy_revision。不能泛用于普通 Bisheng API
厂商 License厂商签发 → Gateway 离线验签RS256，厂商持私钥；Gateway 仅持可信公钥。与用户 access、服务认证三套 key 分离

内部委托在收到上传请求头时验签；传输租约与字节限额约束整个上传。30 秒凭证有效期不等于大文件必须 30 秒传完。commit 是新请求，重新校验当前用户、feature、目标空间与额度。

现有 HMAC canonical 限制小型 body，适合身份/管理控制请求，不适合整个上传正文。内容完整性由 Bisheng 计算 SHA-256、核对 init/commit 声明和字节计数；内部传输使用受控网络与验证证书的 TLS。

防绕过：新知识外部路由必须优先于通用代理；内部路径公网拒绝；外部伪造的身份头全部剥离。普通 Web 知识功能可继续存在，但应拒绝 Work token 并沿用 Web 自己的鉴权。商业授权保证付费 Work API 不被低权限 token 绕过，不保证本机管理员无法修改私有部署。

关键链路时序

箭头为请求或事件，不代表已经实现的 API。控件只切换说明，不调用任何服务。

出错后的行为

401：主进程串行 refresh 一次；非幂等上传 commit 或检索不盲重试。403：按功能、席位、资源权限分别解释，不循环刷新。429：返回 Retry-After。身份、政策或额度依赖不可用：503，阻止新付费操作。

跨步骤的身份不漂移

job 归属在创建时绑定 tenant/user/seat/source。退出或切换企业取消客户端等待；服务端任务归属不改变。旧响应受账户 epoch 阻止，后台作业是否继续由已接受任务合同判断。

授权不是一个 pro 布尔值

基础权利

Work 基础 10 席位

保留 v1.6.0 已有免费基线；需管理员分配。付费扩容到期只撤销超额席位，不删除全部授权和客户文件。

付费 feature

企业知识读写能力

knowledge.retrieve 与 knowledge.upload 分开声明；付费到期关闭。选择基础套餐是否赠送试用，由签名试用授权明确表达。

共享资源

容量 / 解析 / 调用包

企业购买额度，管理员分配到组织与额度池；用户同时受角色配额限制。商业限额不能放宽既有资源 ACL。

建议首期售卖：年度 Work 扩容席位 + 企业知识模块 + 共享容量与解析包。不按插件安装次数收费，不在此草案中虚构价格。模型费用与知识解析/检索费用分账。

示例结构需在正式 schema 中固定数字、字段和时间类型。现有严格 schema v2 parser 不能接受此扩展；先升级服务端，再导入新 License。保留 dsh_entitlement 外层字段及 v2 的 legacy_binding 规则，避免新增第二个外层扩展后破坏旧签名绑定。

厂商签发端保管私钥，Gateway 只验签。外层 legacy 的“加密”本身不能证明授权来自厂商；新增商业权利仅信任签名内层。应用启动时验证完整签名、固定 alg/kid/issuer/audience、部署/企业绑定、有效期与 revision，失败时基础授权和付费授权分别投影。

私有部署通过注册 deployment_id、持久化已接受最高 revision 和签名 revocation 快照防止普通旧包回滚。多副本共享 SQL 投影与授权版本，不能每副本自行覆盖旧 revision；联网撤销即时同步，断网撤销只能在约定离线窗口内生效。离线方案不宣称可即时撤销，也不宣称能抵御客户管理员修改程序或数据库。

商业合同与资源账本分工

Gateway 是授权准入权威；Bisheng 是知识消耗账本权威。沿用当前 QuotaService 的角色/租户链和存储统计，新增可靠预占与结算。两边不能各扣一次。

并发扣量

  1. 租户、根组织、角色和额度池按固定顺序锁定，事务中计算剩余量。
  2. 同一 idempotency_key + 相同摘要返回原任务；不同摘要返回 409。
  3. 接受任务时绑定 reservation；处理成功结算；失败或暂存过期释放。
  4. 未知结果查询 job；重试/补偿不生成第二次结算。

不要把网络调用或解析过程放进数据库事务。reservation 超时清理须先查询任务终态，不能把仍在运行任务的余额重新卖出。

计量口径

  • 存储：按实际对象字节与明确版本保留规则；删除后释放，已解析用量不退款。
  • 解析：成功页数；需要入队前准确预占时先计页，不可计页格式使用合同规定单位/上限。不能无限量先运行后扣费。
  • 检索：完成授权过滤并持久化结果时结算一次；空结果是否收费需合同明确，建议成功空召回算一次。
  • 模型：由模型链路结算，知识检索工具不再次收一笔“答案生成”费用。

额度池与集团结构

首期建议 work_dedicated：Work 商业解析/检索额度单独计量；真实存储沿用同一对象统计，避免同一文件重复计算。若客户采购共享套餐，显式改为 shared_with_web。角色配额、叶子组织限额与根组织上限均需满足，共享资源授权不能把 sibling 租户的数据或用量合并到当前用户可见结果。

Gateway 签名合同的组织总量通过可靠配置同步到 Bisheng；按 revision 幂等确认。同步未完成返回 dependency_unavailable，而非恢复不限额。Gateway 不向客户端承诺已经完成额度激活。

必须覆盖的负向用例

  • 公网访问内部路径、路径编码/尾斜线、未知 method；通用 proxy 不应兜底绕过。
  • 旧模型 token、scope 不足、伪造 tenant/user 头、session/seat 撤销。
  • 空间可见但文件隐藏、主版本过滤、引用权限被撤销。
  • 多个请求并发争抢最后一份额度，多副本与重试不超卖。
  • 上传实收超过 Content-Length/合同限额、流式背压及 Buffer 释放。
  • License 错签、外层 binding 变化、旧 revision、过期、轮换、断网。

迁移与回滚

  • 先增加 schema/table/verifier，不替换 v1；旧客户端继续旧路由。
  • 后部署 Bisheng identity/ACL/quota 适配，再开 Gateway feature flag，再发布 plugin。
  • License v3 在全部节点支持后导入。回滚旧 Gateway 前须恢复有效 schema v2 授权；否则旧 parser 将拒绝 v3 并回落 10 席位。
  • 回滚关闭知识入口与新任务；保留数据、usage/reservation/outbox，完成对账和已有任务，不直接删表。

建议产品先决定的三件事

  1. 延续 1.6.0 的基础 10 席位，还是改为全付费？本方案延续；与当前 main 的授权行为有差异，需要明确产品决定。
  2. 知识模块随扩容套餐包含，还是单独售卖？合同使用独立 feature，两种产品定价都能支持；建议企业套餐包含，保留加购能力。
  3. Work 与 Web 的额度是否共享？建议首期解析/检索独立、真实存储不重复计量，采购合同时明确。
